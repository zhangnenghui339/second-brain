# 高频验证与渠道所有权原子（六门互补）

> 用途：从 Levelsio / 验证讨论中提炼可复用原子，补强「三红线 + 六门」，不取代它们。  
> 一句话：**六门决定“值不值得建”；这些原子决定“怎么试、怎么杀、别把别人的渠道当成自己的验证”。**

## 当前结论

1. 「自己的痛点」是高命中启发式，不是硬红线；等价物是**深度链接反馈回路**（自己用 / 高频代用 / 一线客服）。
2. **买量探针 ≠ 买量增长**：封顶预算测付费意愿合法；把广告撑起的活跃当产品被验证不合法。
3. 抄产品同时抄了三样东西，可复制性递减：**功能 > 痛点 > 渠道**；渠道再拆为可得性 / 成本 / 所有权。
4. 真正可复利的往往是**决策规则**（大失败沉淀 1 条），不是每次小失败的深度复盘。
5. Shotgun 有效的前提是 L1–L5 硬筛 + 单次试错成本够低；不是乱做。

## 原子清单（可单独引用）

| ID | 原子 | 一句话 |
|---|---|---|
| A1 | 深度链接痛点 | 优先自己痛；否则必须有稳定反馈回路，禁止纯脑内用户 |
| A2 | 浪潮窗口 | 做「刚被验证未饱和」的产品化，不做需求创造幻想 |
| A3 | 两周单人上限 | 需要团队/融资才能起步的想法，直接过滤 |
| A4 | Day-1 收费 | 付费墙代替调研；活跃/点赞/Waitlist 是噪音 |
| A5 | 探针买量 | 允许小额买量测支付漏斗；禁止把广告当增长成功证据 |
| A6 | 先卖后自动化 | Kill Criteria 期可人工交付；主飞轮必须回到秒交付 |
| A7 | 市场筛选 | 不预测爆款；压低单次成本 + 提高试错频率 |
| A8 | 杀停阈值 | 「两周能上线 × 上线就收费 × 30 天内真实付费」不达标则下一枪 |
| A9 | 邻接扩张 | 粘住后再做同一受众下一刚需；冷市场另算 |
| A10 | 渠道三维 | 可得性 / 成本 / 所有权分开审计；抄产品抄不走后两者 |
| A11 | 旧雇主折扣 | 老东家验证过的痛点 = 优先测试假设，≠ 你已独立验证 |
| A12 | 指标分层 | 有流量≠有生意；有销量≠有利润；launch 尖峰≠成功 |
| A13 | 规则复利 | 仅大失败升格为规则；小失败丢弃，控制复盘成本 |
| A14 | 自有流量池 | Email / SEO / 可复用名单是 Class 级分发资产，不是装饰 |

## 与六门 / 三红线的互补映射

| 现有门/红线 | 缺口 | 原子补强 |
|---|---|---|
| 红线 1 不做生成类 | 仍成立；Levels AI 写真是他的路径，不是你的 | 不改红线；浪潮窗口(A2)只用于你允许的赛道形态 |
| 红线 2 不做 auto-apply | 仍成立（平台执行层） | 对齐 A10：平台推荐位 = 租来的渠道 |
| 红线 3 不砍 outcome | 仍成立 | A14：outcome + Email 同属不可轻易放弃的复利资产 |
| 门1 他人已验证 | 缺「窗口是否未饱和」「旧雇主≠自己」 | A2 + A11 |
| 门2 先愿付费 | 缺探针买量合法边界与 30 天杀停 | A4 + A5 + A8 |
| 门3 零平台依赖 | 已强；可显式接渠道所有权语言 | A10 |
| 门4 资产秒交付 | 与「先人工再自动化」看似冲突 | A6：实验可重，主闭环必须轻 |
| 门5 沉淀复利 | 偏资产列表；缺决策规则复利 | A13 + A9 |
| 门6 低获客成本 | 「严禁 Paid Ads」过粗 | A5 区分探针/引擎；A10 三维审计 |

## 明确不升格进红线的东西

- 「必须只做自己的痛点」——与系统型杠杆、QuickFox 类案例冲突；降为 A1 软筛。
- 「禁止一切广告」——与门2 Fake-door 冲突；改为探针合法、引擎非法。
- 「失败率 5% 所以要做 70 个」——无自有流量池时抄频率会破产；频率上限由预算与两周约束决定。
