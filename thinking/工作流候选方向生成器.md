# 身份—工作流—数据复利模型：AI 创业的方向发现框架

## 当前结论

“九门”解决候选项目**值不值得做**，但不负责回答更前置的问题：

> **高质量候选方向从哪里来？**

如果候选方向质量很低，再严格的筛选也只能选出“相对不差”的 Idea。因此，九门之前需要一个方向生成系统：它不从趋势榜、SaaS Idea List 或竞品榜单出发，而从创业者长期进入的身份、真实 Workflow、Distribution、Friction 与行为数据出发。

```text
身份 Identity
→ 人群 Audience
→ 工作流 Workflow
→ 分发现场 Distribution
→ 摩擦 Friction
→ 工具 Tool
→ 行为数据 Behavior Data
→ 结果数据 Outcome
→ 数据库 Database
→ 更强产品与更低成本分发
```

这不是一个单品方法论，而是一个能持续产生产品、数据与分发优势的长期创业操作系统。

## 一、模型一：身份认同——先选长期进入的现实

传统创业路径是：

```text
发现市场 → 选择产品 → 学习用户 → 尝试进入行业
```

更稳定的路径是：

```text
确定长期身份 → 进入真实工作流 → 持续遇到问题 → 产品自然产生
```

身份决定每天接触什么问题、掌握什么语言、获得什么一手数据。Developer 长期接触 Debug、PR 与部署；Creator 接触选题、发布与 CTR；Seller 接触选品、广告与订单；Solo Founder 接触需求验证、收款、SEO、客服与自动化。

长期主航道先过一句：

> **如果未来三年没人逼我，我是否仍会每天做这件事？**

- **会：** 有资格成为长期主航道，因为能持续获得一手 Friction、语言、数据和分发信号。
- **不会：** 即使市场成立，也只适合作为受控实验或短期项目。

当前更稳定的身份不是“Career 创业者”，而是：

- 长期创业身份：**AI-native Global Solo Founder**；
- 日常操作身份：**AI Workflow Operator**；
- CareerRadar：垂直实验场，不承担身份本身；
- Codex、Cursor、Claude Code、GPT：Builder 工具，不是长期驻留状态。

“中年男人”是人口标签，不是工作流；“AI-native Global Solo Founder”则对应找需求、验证、收款、SEO/GEO、Affiliate、Agent、自动化与增长等可观察任务。

## 二、模型二：第一性原理——从任务约束推导产品

产品存在，不是因为别人已经做了，而是因为某类用户在某个工作流中存在持续摩擦。

不要先问“做 PDF 工具还是 Resume 工具”，先问：

1. 谁在完成什么任务？
2. 任务发生在什么场景？
3. 哪一步重复、低效、等待久或容易失败？
4. 用户目前如何勉强解决？
5. 哪些行为可以被技术替代？
6. 结果是否可以量化？

“PDF 压缩”只是功能，不是完整需求。真实需求可能是 Gmail 用户要把附件压到 25MB 以下、Discord 用户要满足上传限制、求职者要满足 ATS 或招聘网站要求。同一功能背后，Search Intent、付费动机和分发位置完全不同。

因此，产品应从以下交集推导：

> **特定人群 × 特定任务 × 特定限制**

## 三、模型三：系统思维——工具只是增强回路的入口

线性创业模型是：

```text
做产品 → 获得用户 → 收入
```

系统创业模型是：

```text
工具 → 用户行为 → 数据 → 更强结果
→ 更高留存 → 更多用户 → 更多数据
```

一个窄工具的价值不只在当下收入，而在于是否同时产生三类资产：

| 资产 | 核心问题 |
|---|---|
| **现金资产** | 用户是否愿意直接付费？ |
| **数据资产** | 每次使用是否沉淀输入、行为、失败、偏好和 Outcome？ |
| **分发资产** | 数据能否生成 SEO 页面、Benchmark、报告、案例、推荐和口碑？ |

完整飞轮是：

```text
真实工作 → 发现摩擦 → 脚本解决 → 产品化收费
→ 收集行为数据 → 收集 Outcome → 形成数据库
→ 提升产品 → 降低 CAC → 扩展邻接产品
```

系统思维的关键不是“当前工具赚多少钱”，而是：

> **它是否让下一个产品更容易成功？**

## 四、模型四：概率世界观——用低成本证据更新方向

创业不是寻找确定答案，而是运行一系列概率实验。

错误问题是：“这个方向到底对不对？”正确问题是：

> **当前信息下，它有多大概率成立？我用什么最低成本获得下一条关键证据？**

```text
先验判断 → 小成本测试 → 获得新证据
→ 更新概率 → 加注、调整或停止
```

每个 MVP 只是一次采样。第一版数据不好不等于方向必错；第一版数据好也不等于商业模式已经稳定。两周 MVP、Day-1 收费与 30 天验证的作用，是快速取得能改变后验概率的证据。

好的实验应具备不对称性：下行只损失有限时间和预算；上行可能得到现金流、SEO、数据与可复用 Engine。即使成功率不高，只要下行被锁定、上行可复利，仍可能是正期望值。

## 五、模型五：分发—任务契合——需求现场就是入口

分发不是产品完成后的流量问题，它本身定义用户所处的任务状态：

- Gmail 用户正在处理附件；
- GitHub 用户正在提交代码；
- LinkedIn 用户正在查看职位；
- ChatGPT 用户正在尝试完成任务；
- 手机相册用户刚完成拍摄。

| 维度 | 核心问题 |
|---|---|
| Who | 用户是谁？ |
| Workflow | 他在完成什么任务？ |
| Where | 任务在哪里发生？ |
| When | 哪个时刻最需要帮助？ |
| Tool | 什么工具应当自然出现？ |

真正好的工具不只满足需求，还在正确场景、正确时间出现。Skill、MCP、ChatGPT App、IDE Plugin 等新入口的价值，也在于它们聚集了明确用户并暴露新的工作流摩擦。

## 六、模型六：信息不对称——从用户说什么走向用户做什么

公开搜索数据能说明用户说了什么；真正高价值的是用户做了什么。

| 层级 | 数据 |
|---|---|
| Intent | 搜索词 |
| Expression | 评论、抱怨、Issue |
| Behavior | 修改、复制、重试、放弃 |
| Execution | Tool、Skill、MCP 调用与实际结果 |

越接近 Execution，数据价值越高、公开程度越低。创业者获取这类数据的方式不是继续搜索，而是进入工作流、做一个真实工具，成为需求现场的一部分。

工具因此既是价值交付产品，也是数据采集入口。只有掌握别人看不到的 Behavior 与 Outcome，才形成真正的信息不对称。

## 七、模型七：激励机制——优先服务离钱更近的个人用户

关键不是 B2B 还是 B2C，而是用户离钱有多近。Creator、Seller、Developer、Marketer、Job Seeker 与 Solo Founder 虽然很多是个人用户，但购买工具通常是为了：

- 增加收入；
- 节省生产时间；
- 降低获客成本；
- 提升转化率；
- 降低风险；
- 获得工作机会。

他们是 **Professional Consumer**。工具结果离用户收入越近，预算越容易成立。因此优先寻找：

> **高频工作流 × 明确 ROI × 个人可直接决策购买**

## 八、模型八：二阶思维与复利——每次试错都增强下一次

一阶思维问“这个工具能否赚钱”；二阶思维问“它会沉淀什么”；三阶思维问“这些沉淀如何改变下一次创业的成功率”。

例如，一个 PDF 工具的一阶价值是广告或订阅；二阶价值是压缩、OCR、文件处理模块；三阶价值是形成 Workflow Utility Engine；四阶价值是让 SEO、支付、Email 与数据体系在邻接产品中重复复用。

真正的复利不是一个产品永久增长，而是：

> **每一次试错都增强下一次试错能力。**

长期项目必须通过 Stop Test：

> **如果今天停止主动投入，是否仍留下流量、数据、用户关系、代码模块或收入？**

停止后什么都不剩，它只是工作，不是资产。

## 九、执行系统：Operator、Builder 与 Research

| Mode | 建议占比 | 任务 | 退出条件 |
|---|---:|---|---|
| **Operator** | **70%** | 做真实业务、使用工具、接触用户、记录 Friction 与 Outcome | 发现可验证的重复摩擦 |
| **Builder** | **20%** | 用 Codex 等把已知摩擦变成脚本、SOP 或窄工具 | 问题被解决并回到真实工作流 |
| **Research** | **10%** | 跟踪新能力供给、渠道和市场变化 | 新能力已映射到具体 Friction；否则停止 |

默认状态是 Work / Operator，不是持续停留在 Codex。进入 Builder 的默认触发器：

```text
同一动作重复 ≥ 3 次
且自动化 ROI 为正
→ 写最小脚本
→ 自己继续使用
→ 验证是否有人愿意付费
→ 记录 Outcome
→ 返回 Operator
```

不能映射到具体 Friction 的新工具、新模型和新闻，只是能力供给，不是商机。

## 十、Workflow Journal：记录证据，不维护 Idea List

每条观察至少记录：

| 字段 | 内容 |
|---|---|
| Workflow | 当时要完成的真实任务 |
| Friction | 卡在哪里，为什么卡 |
| Frequency | 已发生次数 / 预计频率 |
| Cost | 时间、金钱、风险或机会损失 |
| Workaround | 当前如何手工绕过；是否已写临时脚本 |
| Distribution | 还有谁在同一现场遇到它；如何触达 |
| Outcome / Asset | 解决后的结果，以及留下的数据、内容、名单、代码或规则 |

只有具备真实发生记录的 Friction 才能成为候选；纯脑暴 Idea 不进入九门。

```text
Operator 真实工作
→ Friction Journal
→ Builder 最小解决
→ 自用复测
→ Day-1 收费 / Deposit 验证
→ Outcome Data
→ pSEO / Email / Database / Module
→ 更多真实用户与新 Friction
```

真正的复利资产不是孤立产品，而是：

```text
Workflow → Behavior → Outcome → Database
```

每做一个工具都问：**这次使用会留下什么不可回填的数据或可重复触达权？** 如果答案是“什么都不留”，它至多是一次性效率脚本，不应被误判为长期业务。

## 十一、进入九门前的五项标准

候选方向至少满足五项，才值得进入九门：

1. **真实身份：** 自己是重度用户，或拥有等价的高频反馈回路；
2. **高频工作流：** 问题重复出现，不是低频偶发需求；
3. **明确 ROI：** 能帮助用户赚钱、省钱、省时间或降低风险；
4. **天然分发场景：** 工具能够出现在问题发生的地方；
5. **数据沉淀：** 每次使用能够积累 Behavior 或 Outcome。

最终形成两层体系：

```text
第一层：方向生成
身份 → 人群 → 工作流 → 分发 → 摩擦 → 数据

第二层：九门筛选
对候选做完整体检，决定是否允许投入并构建 MVP
```

第一层负责产生更好的候选，第二层负责避免把资源押在错误候选上。完整九门见 [`../projects/careerradar/决策原则_红线与MVP反脆弱九门.md`](../projects/careerradar/决策原则_红线与MVP反脆弱九门.md)。

这套体系的最终目标不是找到某一个产品，而是把创业从“寻找 Idea”转化为长期系统：

> **生活在未来工作流里，用最新技术解决真实摩擦，让工具成为数据入口，让每一次试错都积累下一次成功所需的资产。**

## 反模式

```text
Research → Research → Research
```

结果：认知增加，没有真实 Workflow，也没有收费验证。

```text
Builder → Builder → Builder
```

结果：持续写代码，但没有一手 Friction、分发现场和 Outcome。

正确循环：

```text
Work → Friction → Build → Reuse → Charge → Data → Work
```
