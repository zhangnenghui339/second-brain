# 工作流候选方向生成器：从真实摩擦到九门候选

## 当前结论

**先选长期身份与真实工作流，再从反复发生的 Friction 中生成候选；九门负责过滤候选，不负责凭空产生 Idea。**

- 长期创业身份：**AI-native Global Solo Founder**。
- 日常操作身份：**AI Workflow Operator**。
- CareerRadar：一个垂直实验场，不再承担身份本身。
- Codex / Cursor / Claude Code / GPT：Builder 工具，不是长期驻留状态。

核心链路：

```text
身份（Who）
→ 真实工作流（Workflow）
→ 分发现场（Distribution）
→ 可重复摩擦（Friction）
→ 临时脚本（Script）
→ 窄工具（Tool）
→ 行为与结果数据（Data / Outcome）
→ 三红线、六因子、五关、九门
```

## 一、候选方向从哪里来

不要先问「做什么产品」，先问：

1. **Who：** 我愿意连续三年成为谁？
2. **Workflow：** 这个身份让我每天反复完成哪些真实任务？
3. **Distribution：** 我在哪里天然接触同类人、搜索意图、社区问题或客户回信？
4. **Friction：** 哪些动作反复、昂贵、易错、等待久，或需要跨多个工具？
5. **ROI：** 消除摩擦后，能节省多少时间、成本或风险，或直接增加多少收入？
6. **Data：** 每次使用会留下什么行为、决策或 Outcome 数据？

这六项是**候选生成证据**，不是新的六道 Gate。候选生成后，仍须进入三红线、六因子排序、五关推进与九门放行。

### Founder–Workflow Fit

长期主航道先过一句：

> **如果未来三年没人逼我，我还会不会每天做这件事？**

- **会：** 有资格成为长期主航道候选，因为能持续获得一手摩擦、语言、数据与分发信号。
- **不会：** 即使市场大，也只适合作为受控实验或短期项目，不作为长期身份。

人口标签不是工作流。「中年男人」「创业者」过于宽；「AI-native Global Solo Founder」对应找需求、验证、收款、SEO/GEO、Affiliate、Agent、自动化与增长等可观察工作流。

## 二、Work 是默认状态，Builder 是局部状态

| Mode | 建议占比 | 任务 | 退出条件 |
|---|---:|---|---|
| **Operator** | **70%** | 做真实业务、使用工具、接触用户、记录 Friction 与 Outcome | 发现可验证的重复摩擦 |
| **Builder** | **20%** | 用 Codex 等把已知摩擦变成脚本、SOP 或窄工具 | 问题被解决并回到真实工作流 |
| **Research** | **10%** | 跟踪新能力供给、渠道与市场变化 | 新能力已映射到具体 Friction；否则停止 |

默认状态是 **Work / Operator**，不是持续停留在 Codex。进入 Builder 的默认触发器：

```text
同一动作重复 ≥ 3 次
且自动化 ROI 为正
→ 写最小脚本
→ 自己继续使用
→ 验证是否有人愿意付费
→ 记录 Outcome
→ 返回 Operator
```

研究也必须服务于已知工作流：**不能映射到具体 Friction 的新工具、新模型和新闻，只是能力供给，不是商机。**

## 三、记录 Workflow Journal，不维护 Idea List

每条观察最少记录：

| 字段 | 内容 |
|---|---|
| Workflow | 当时要完成的真实任务 |
| Friction | 卡在哪里，为什么卡 |
| Frequency | 已发生次数 / 预计频率 |
| Cost | 时间、金钱、风险或机会损失 |
| Workaround | 当前如何手工绕过；是否已写临时脚本 |
| Distribution | 还有谁在同一现场遇到它；如何触达 |
| Outcome / Asset | 解决后结果，以及留下的数据、内容、名单、代码或规则 |

只有具备真实发生记录的 Friction 才能成为候选；纯脑暴 Idea 不进入九门。

## 四、闭环与资产边界

```text
Operator 真实工作
→ Friction Journal
→ Builder 最小解决
→ 自用复测
→ Day-1 收费 / Deposit 验证
→ Outcome Data
→ pSEO / Email / Database / Module
→ 更多真实用户与新 Friction
```

真正的复利资产不是某个孤立产品，而是：

```text
Workflow → Behavior → Outcome → Database
```

每做一个工具都问：**这次使用会留下什么不可回填的数据或可重复触达权？** 如果答案是「什么都不留」，它至多是一次性效率脚本，不应被误判为长期业务。

## 五、与 CareerRadar 及九门的关系

- CareerRadar 可以继续存在，但定位为 **AI Workflow Engine 的垂直实验场**。
- Career、SEO、Creator、Affiliate 等是不同应用域；能跨域复用的是脚本、Agent 管线、验证规则与数据结构，域名权威、用户名单和垂直 Outcome 数据仍属于实例层。
- 本框架只回答「高质量候选从哪里来」；[`../projects/careerradar/决策原则_红线与MVP反脆弱九门.md`](../projects/careerradar/决策原则_红线与MVP反脆弱九门.md) 回答「候选值不值得投入并构建 MVP」。

## 反模式

```text
Research → Research → Research
```

结果：认知增加，没有真实 Workflow，也没有收费验证。

```text
Builder → Builder → Builder
```

结果：持续写代码，但没有一手 Friction、分发现场和 Outcome。

正确循环：

```text
Work → Friction → Build → Reuse → Charge → Data → Work
```
