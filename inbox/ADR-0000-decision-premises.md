# ADR-0000: 决策前提与依赖规则（AI 格局约束层）

- **Status**: Accepted
- **Date**: 2026-07-15
- **Type**: Constitution（宪法层——本文件是所有后续 ADR 的强制依赖）
- **Review cycle**: 每 90 天 / 任一 Tripwire 触发时

---

## 0. 本文件的作用与使用规则

1. 每一条新 ADR 的 frontmatter 必须包含 `premises: [P1, P3, ...]` 字段，声明其依赖的前提。
2. 当某前提状态从 `HOLDING` 变为 `BROKEN`，所有依赖该前提的 ADR 自动进入复审队列（grep `premises:.*P{n}` 即可拉出清单）。
3. 每一条新 ADR 必须通过第 3 节的情景测试（S1–S4），在正文中逐条写明「该决策在此情景下的存活性」。
4. 本文件本身不可变；前提状态变更通过追加 `## Amendment Log` 条目实现，不修改原文。

## 1. 决策前提（Premises）

> 状态取值：HOLDING（成立）/ WEAKENING（弱化中）/ BROKEN（已失效）

### P1 — 生成层已商品化，永久不进入
- **内容**：AI 使简历/内容/代码生成的边际成本趋近于零。任何以「生成」为核心价值的产品（Resume Builder、Cover Letter 生成、批量 SEO 内容）都处于无限供给赛道，终局归模型厂商与大厂全家桶。
- **推论**：CareerRadar 永不构建以生成为主要付费点的产品；内容资产（Review/对比页）只作为获客管道（Class B 折旧资产），不计入核心资产。
- **状态**：HOLDING

### P2 — 生成过剩制造验证稀缺（裁判位成立的根基）
- **内容**：当所有简历都由 AI 生成且「看起来完美」，甄别与验证成为新稀缺。运动员（Rezi/Jobscan/BOLD 系）因收入结构无法自证，平台（LinkedIn）因双边收费无法中立。中立裁判位在结构上只能由独立第三方占据。
- **推论**：核心付费产品 = Verified ATS Parse Report；方法公开（Wirecutter 透明模型），防御性来自经济摩擦 + 解读 baseline + 累积基准库三要素，而非方法保密。
- **状态**：HOLDING
- **失效条件**：见 S1 / S2。

### P3 — Outcome Ground Truth 是唯一 Class A 资产
- **内容**：全行业有生成量数据，无人有「这份简历最终是否拿到面试/offer」的真值闭环。该数据不可回填（错过收集窗口即永久缺失）。
- **推论**：任何产品决策若与 Day 1 outcome 收集冲突，outcome 收集优先。四级摩擦阶梯（L0 一键跟进邮件为主）不可降级删除。
- **状态**：HOLDING

### P4 — 分发正从 SERP 排名迁移到 AI 引擎引用（GEO）
- **内容**：AI Overviews / ChatGPT / Perplexity 持续蚕食 informational SEO 点击。「被引用」取代「被排名」。AI 引擎的引用偏好：结构化、可验证、有原始数据、中立信源——与裁判定位天然耦合。
- **推论**：所有内容产出必须同时满足 SEO 与 GEO 双标准（L1/L2/L3 citation depth 框架）；关键词战场限定在工具词、验证词、长尾意图词，永不进攻 "ai resume builder" 类头部大词。
- **状态**：HOLDING

### P5 — 简历的读者已经是机器，且格式本身有死亡风险
- **内容**：简历的实际第一读者是 parse 引擎与 semantic graph（LinkedIn Semantic Skill Graph 为标志）。短期这论证了机器可读性验证的需求；长期（agent-to-agent 招聘成熟时）PDF 简历可能被结构化 profile / 协议标准取代。
- **推论**：短期加注 parse 验证；长期不下注格式之争，但监控 S3 情景。测试基建设计时，解析对象抽象为「候选人数据 → 目标系统」而非硬编码「PDF → ATS」。
- **状态**：HOLDING（短期）/ 监控中（长期）

### P6 — 单垂直存活不确定，系统可迁移性是最终对冲
- **内容**：AI 能力上移速度不可预测，任何垂直（包括裁判位本身）都可能被引擎层原生吞掉。项目级失败必须不等于资产归零。
- **推论**：Engine（Search Demand 监控、pSEO 管线、prompt 库、GEO 能力、测试方法论）与 Payload（CareerRadar 专属）物理分仓；Engine 仓库禁止垂直领域硬编码；Kill Criteria 一律写为 Pivot Criteria。
- **状态**：HOLDING（公理级，不设失效条件）

## 2. 业态地图（决策的定位坐标系）

每条新 ADR 必须声明其所处层级；投入 1/4/6 层的提案默认否决，需超额论证。

| 层 | 业态 | 终局归属 | 政策 |
|----|------|---------|------|
| L1 | 生成层（builder/内容） | 模型厂商 + 大厂 | ❌ 禁入（获客管道除外） |
| L2 | 验证/裁判层 | 独立第三方（空位） | ✅ 主战场 |
| L3 | Outcome 数据层 | 先建闭环者独占 | ✅ Day 1 强制 |
| L4 | 代理执行层（auto-apply） | 平台原生 | ❌ 禁入 |
| L5 | 引用/分发层（GEO） | 中立结构化信源 | ✅ 与 L2 耦合建设 |
| L6 | 格式/协议层 | 大厂 + ATS 厂商标准之争 | ⚠️ 只监控不下注 |

## 3. 情景测试（每条 ADR 必答）

### S1 — 引擎层吞掉裁判位
- **情景**：OpenAI / Perplexity / Google 原生推出「简历实测/工具排名」，它们无利益冲突且拥有引用入口。
- **早期信号（Tripwire）**：任一主流 AI 引擎发布垂直评测类官方产品；ChatGPT 插件/GPTs 生态出现官方认证的 ATS 测试能力。
- **触发动作**：P2 降级为 WEAKENING → 复审所有依赖 P2 的 ADR → 评估从「面向用户的裁判」转型「面向引擎的数据供应商」（把基准库卖给引擎，而非与引擎争夺用户）。

### S2 — 验证被官方 API 商品化
- **情景**：Greenhouse / Lever / Workday 开放官方 parse-preview API，任何人零成本获得权威解析结果。
- **早期信号**：ATS 厂商开发者文档出现候选人侧 parse endpoint；竞品宣称「官方数据源」。
- **触发动作**：实测数据护城河失效，但解读 baseline 与 outcome 闭环（P3）不受影响 → 产品重心从「测」转向「解读 + 跨样本对比 + outcome 关联」。

### S3 — 简历格式死亡
- **情景**：结构化 profile 标准（agent-to-agent）取代 PDF 投递成为主流。
- **早期信号**：LinkedIn / Indeed 推出机器可读 profile 直投协议；主要 ATS 支持免简历申请占比显著上升。
- **触发动作**：P5 长期分支激活 → parse 测试对象从「PDF→ATS」迁移为「profile→matching graph」，验证需求不消失，验证对象改变；Engine 层测试框架因抽象设计可平移。

### S4 — GEO 渠道依赖恶化
- **情景**：AI 引擎引用集中度进一步提升，或引入付费引用位，独立站引用份额被压缩。
- **早期信号**：引用来源中大媒体/付费伙伴占比持续上升；自然引用监测连续两个周期下滑。
- **触发动作**：P4 降级 → 分发权重向 email list（自有渠道，唯一不可没收的分发资产）与社区口碑倾斜；drip 序列与 list 增长指标升级为 hard-gate 级监控。

## 5. 依赖图

```
P6 (系统可迁移) ──宪法级公理，兜底一切
   │
P1 (生成商品化) ─┬→ 禁入 L1/L4 → 内容仅作管道
P2 (验证稀缺)   ─┼→ L2 裁判位 = 主战场 ←─ S1/S2 监控
P3 (Outcome A类) ┼→ L3 Day 1 强制 ←─ 不受 S1/S2 影响（最深护城河）
P4 (GEO 迁移)   ─┼→ L5 与 L2 耦合 ←─ S4 监控 → email list 兜底
P5 (机器读者)   ─┴→ 短期 parse 验证 / 长期 S3 监控 → 抽象化测试框架
```
