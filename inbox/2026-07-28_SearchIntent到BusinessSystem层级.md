# Search Intent → Business System 层级栈

> inbox 原料。未展开定义，仅先记下层级关系。

```
Search Intent
    ↓
Workflow
    ↓
Dataset
    ↓
Agent
    ↓
Business System
```

## 层级（自上而下）

1. **Search Intent** — 搜索意图
2. **Workflow** — 工作流
3. **Dataset** — 数据集
4. **Agent** — 智能体
5. **Business System** — 业务系统

## 关系备忘

- 上层约束下层：意图定义工作流，工作流塑造数据集，数据集喂给 Agent，Agent 嵌入业务系统。
- 待补：每一层的边界、输入输出、与 CareerRadar / 现有项目的映射。

## 创始人的价值正在变化

未来最值钱的不一定是：

- 写 Prompt
- 写代码
- 写文章

而是：

- 定义市场
- 定义数据结构
- 定义 Agent Workflow
- 定义产品边界

这些决定了 AI 应该去执行什么。

## 推论

推论是「产品形态必须由分发通道反推」→ 这是对的。

## 五关闸门（链条倒过来）

把链条整个倒过来，每一关都是「能否继续」的闸门，而不是一次性规划：

| 关卡 | 要回答的问题 | 通过判据 | 时间量级 |
|---|---|---|---|
| G1 分发 | 第 100 个用户从哪来？成本多少？ | 说得出具体渠道与获客成本量级；「做 SEO」不算答案，「某类关键词、月搜索量 X、竞争度 Y」才算 | 天 |
| G2 变现 | 谁付钱？付多少？为什么现在付？ | 该 CAC 下的价格带在市场中已被验证存在 | 天 |
| G3 需求 | 有人愿意为承诺付出真实成本吗？ | 落地页 / 预售 / 邮件列表拿到非零转化 | 1–2 周 |
| G4 最小交付 | 能否手工交付一次完整价值？ | 有人付费并获得结果，哪怕全靠人力 | 2–4 周 |
| G5 产品化 | 哪一步值得写成代码？ | 手工交付已重复 N 次，瓶颈明确 | 之后才开始 |

## 能力稀缺度（大致占比）

| 能力项 | 大致占比 |
|---|---|
| 15 年+ 独立工程能力 | ~1/100 |
| 大厂产品管理经验 | ~1/50 |
| 海外性能营销实操（非理论） | ~1/100 |
| 中/英/日跨市场可操作 | ~1/50 |
| 愿意长期无协作、系统化独立运行 | ~1/20 |

## 选点原则

不是从痛点出发，也不是从空白出发，是从「你已有分发权的场域」里找痛点。

方向来源是一个**交集**，不是任一单点：

```
① 你有不对称的领域（工程 + SEO + 跨市场 + 长期无协作）
        ∩
② 你能低成本获得分发权的场域（英文搜索场、已建的关键词矩阵、正在积累的邮件列表）
        ∩
③ 该场域内可观测到的真实痛点（从搜索词、社区提问、用户回信里读，不是从自己身上读）
```
