复盘笔记 · Pieter Levels 选品与失败框架

不是选中了好产品，
是把试错成本压到了足够低。

梳理 Pieter Levels 的项目选择逻辑、失败教训与可复制边界，并与 CareerRadar 自有的「MVP 反脆弱六门 + 三红线」决策框架做逐条对照——判断两者是同一件事的递进改写，还是各自独立的维度。

01 核心方法论

五个动作，构成他挑项目、验证项目、放弃项目的完整闭环。

A

问题从自己来（Scratch Your Own Itch）

观察自己生活里缺失的信息或烦恼的事，因为自己就是用户，不需要花几个月理解需求。

不知道去哪座城市远程生活 → Nomad List　·　远程工作者需要工作 → Remote OK
B

紧贴突然出现的新技术能力

不完全来自需求访谈，也来自「技术供给创造产品机会」——先玩新模型，发现某个结果第一次变得可用，几天内挂上支付页面。

Stable Diffusion / DreamBooth / image-to-image → Photo AI、Interior AI
C

先人工交付，再决定是否自动化

Avatar AI 早期：Stripe收款 → Typeform收照片 → 手动训练 → 手动生成 → 手动发送。最初几百单全靠人工，需求爆发后才被迫自动化——本质是「先卖，再写完整软件」，避免在没有需求时投入工程成本。

D

让市场筛选，而不是自己预测

发现问题/新能力 → 几天内做原型 → 公开发布 → 尽快收费 → 看真实购买 → 有增长就继续，没增长就停。他真正擅长的不是「选中好产品」，是把每次试错成本压得足够低、足够快地识别哪个值得继续——这和「成功率高」完全不同，他的项目清单反而证明失败率非常高。

E

他筛选项目的隐性过滤器

  • 时机窗口 — 趋势必须「刚被验证但未饱和」，不创造需求，只做趋势的第一批产品化，是时间套利不是需求创造
  • 复杂度上限 — 一个人两周能独立搞定，需要团队/融资的想法直接过滤，不管市场多大
  • 上线即收费 — 不做纯增长期，免费产品的「用户喜欢」是噪音，付费转化率才是真信号，用付费墙代替市场调研
  • 必须能挂到现有分发渠道 — 12个月12个项目超过95%失败，但失败成本极低，因为每次测试几乎零CAC，代价只是几周开发时间

02 失败教训：从项目到规则

单次失败大多不值得归因，但少数信号足够强的失败，被沉淀成了可复用多次的规则。

Uber Clone (2010)
找富人投资人融资，对方从未真正投资，纯浪费时间且相当羞辱 → 融资路径被永久剔除，此后走「自筹 + 高频低成本试错」，而非「融资 + 押注单一项目」
Tubelytics (2013–14)
花近一年打磨YouTube数据分析后台，界面精致，但没人付钱 → 「先验证付费意愿再动手」规则 → 直接决定了 RemoteOK（day-1收费）、Photo AI（生成即收费）、飞行模拟器（几天内挂Stripe链接）的统一打法。一个失败项目产出的规则，被复用了至少三次成功案例，这才是真正的复利——不是项目的复利，是决策规则的复利
Panda Mix Show (2008–14)
早期YouTube收入来源，因版权申诉规则变化，收入从$8K/月跌到$500-900/月 → 触发了「12 Startups in 12 Months」，更深层教训是：后续所有成功项目都自己掌控域名/用户数据/邮件列表，不再依赖单一平台的规则变化
其余约10个失败
没有具体归因，只有一句「没能起来」——这个空白本身就是信号：高频组合下注策略下，单次失败不值得深度复盘，复盘成本也是成本，只有损失大到威胁继续试错能力的失败才值得沉淀成规则

03 最容易踩的坑：闭门造车

先决定"我要创业"
→ 在趋势报告里找一个赛道
→ 想象用户可能存在的问题
→ 闭门开发半年
→ 上线后再找用户　← 反馈延迟到终点，错误在此期间持续累积

解法只有一句话：在写第一行代码之前先确认有人愿意付钱（挂付款链接/收集意向金），把「验证」从「上线后」移到「动手前」，彻底切断这个失败模式的根。

04 他真正的决策算法

问题从自己来自己不用 / 自己不痛 → 不做
原创性靠人变不一样旅行、边缘场景、非同质生活 → 看到别人看不到的问题；不靠头脑风暴抄同温层
先小后大niche验证后再扩市场（Nomad → travel）
一年一个项目的反面早期12 startups / 12 months；失败成本压到月级
有机流量是裁判停买广告还在涨才算真；假增长不当验证
后期追加一条会维护、付费路径清晰的才做（熵会让产品坏掉）
粘住之后进入「自动化 + 退出日常劳作」循环，然后开下一枪

05 可复制 vs 难抄／易误读

仍可抄难抄 / 易误读
自有问题、小MVP、立刻收费、杀弱加倍他后期有60万级受众，新项目冷启动成本被品牌压低
从已粘住产品做邻接扩张（RemoteOK模式）「散弹枪」被理解成乱做；他其实每枪都有硬筛：自己有没有痛、能不能很快上线、能不能马上收钱、一个人能不能跑、有没有有机流量
跟新技术浪做5天–4周探针（Interior/Avatar模式）叙事里少写失败枪数，Base Rate被幸存者偏差抬高

这两栏在拆同一件事：他表面像「乱开枪」，实际有硬筛；外人抄结论时，容易把「可抄的动作」和「难抄的条件」搞混。

06 获客渠道的三个子维度

「抄产品」同时在处理三个可复制性天差地别的东西，容易被混为一谈。

被复制的对象可复制性说明
产品功能 / UI形态几乎100%可复制最容易，也最没价值的部分
痛点 / 付费意愿部分可复制广谱刚需大概率对陌生用户依然成立；依赖特定场景/信任关系的，换渠道未必成立
获客渠道 + 获客成本最难复制通常是唯一的真护城河，可再拆三层：渠道可得性（能不能进）、渠道成本（陌生玩家要为不被信任支付隐性溢价）、渠道所有权（租的还是自己的——Levels真正的护城河是十年攒下的自有流量池，边际获客成本趋近于零）

07 对照：六门 / 三红线，是递进还是另一维度

CareerRadar 的「MVP反脆弱六门 + 三红线」是把 Levels 的实战经验抽成可执行清单——但不是无损翻译。逐条核对，三种关系并存。

G2

先愿付费

递进 · 一致

Levels对应

「上线即收费，不做纯增长期」铁律，Tubelytics教训直接产出

几乎是同一条规则的两种写法，是六门里唯一被Levels反复、明确验证过的一条，可以直接合并。

G3

零平台依赖

递进 · 一致

Levels对应

Panda Mix Show教训 → 自己掌控域名 / 用户数据 / 邮件列表

因果链清晰：Levels吃过平台规则变化的亏才形成这条规则，六门把它抽象成通用清单，是直接递进。

G6

自有受众与低获客成本

递进 · 核心

Levels对应

十年Twitter自有流量池，全篇反复强调的核心资产（06节）

六门里唯一可以说是直接从Levels经验里「抽出来」的一条，甚至比其他几门更贴近他真实的成功机制核心。

G1

他人已验证

张力 · 需打补丁

Levels对应

隐性过滤器「趋势必须刚被验证但未饱和」+ 「原创性靠人变不一样」

门1要求「已被验证、赢家非通吃」的成熟赛道；Levels实际经常是早期开拓者（Nomad List / RemoteOK上线时都不存在先例），他的「验证」来自趋势时机判断，不是「已有人赚钱」。字面合并会误伤他真正做成的多数案例。

G4

资产秒交付

张力 · 需打补丁

Levels对应

先人工交付再自动化（Avatar AI手动处理早期订单）+ 极简可维护性

Levels的实践是「验证期允许人工，规模化后才自动化」；门4字面要求起量前就秒交付，若不区分「验证期」与「规模期」，会把他自己验证有效的打法误判为不合格。

G5

沉淀复利

张力 · 需打补丁

Levels对应

邻接扩张（RemoteOK吃Nomad List存量受众）+ D资产概念

门5要求「每一单交易本身沉淀资产」（pSEO/邮件列表等）；Levels的复利实际发生在受众/个人品牌这一层，是项目之间的复利，不是单笔交易内的复利——粒度不同，合并时要分清是「单量级复利」还是「组合级复利」。

R1

不做生成类产品

另一维度

Levels对应

无——Photo AI / Interior AI 本身就是生成类产品，且是核心收入

这条红线不是从Levels经验来的，方向甚至相反。它是CareerRadar对自身所在品类（内容/SEO）特有的 AI Overview 吞噬风险的防御，是行业特化产物，不能指望从Levels的经验里推导出来。

R2

不做 auto-apply / 平台执行层

另一维度

Levels对应

无直接对应，泛化地「避开重运营项目」勉强沾边

这是对 LinkedIn 这个具体巨头势力范围的避让，是 CareerRadar 所在细分市场的竞争格局判断，Levels框架里没有「避开巨头地盘」这类具体条款。

R3

不砍 outcome 数据收集

另一维度 · 原创延伸

Levels对应

无——他的产品都不追踪「结果性」数据（照片有没有真的带来面试机会这类）

这条其实是把「沉淀复利」的思路往深处又走了一步：不只是流量/邮件列表可以复利，「结果验证数据」本身也是复利资产，且是求职这个垂类独有的不可回填资产。Levels的工具型SaaS形态不需要这类数据，这是CareerRadar在他的框架之外长出的东西。

一句话结论

六门 + 三红线，不是对 Levels 框架的单一关系，而是三种关系的叠加：三条门是直接递进（把他的实战经验改写成了清单），三条门存在字面张力需要打补丁才能对齐，三条红线基本跳出了他的框架，是 CareerRadar 自己在具体品类风险认知上长出的另一维度——尤其是 outcome 数据红线，这是他完全没有触及、甚至他的产品形态本身就落在其禁区里的东西。
