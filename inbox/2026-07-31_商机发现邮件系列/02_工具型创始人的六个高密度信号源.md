# 邮件 2｜工具型创始人的六个高密度信号源

**Subject：** 别爬全网：工具商机只需要六类高密度信号  
**Preheader：** 先找预算、工作流和失败成本，再找产品。

“全网数据爬取”听起来理性，实际上很容易变成分析型创始人的避难所。

商机雷达不追求数据最多，而追求单位数据里的**预算、摩擦和变化密度**。

针对 Tool / Data Product / Agent，更值得长期跟踪的是六类信号。

## 1. Search Intent 变化

**来源：** Google Trends、Keyword Planner、GSC、Autocomplete、People Also Ask、SEO 数据库。  
**寻找：** 新出现的任务词、错误词、替代词、比较词和“how to automate”类查询。  
**通过信号：** 商业意图词持续增长，并能对应明确工作流。  
**假信号：** 只有新闻热度，没有购买或任务意图。

## 2. 软件评论与公开 Issue

**来源：** G2、Capterra、Chrome Web Store、Shopify/App Marketplace、GitHub Issues、Reddit。  
**寻找：** “太贵”“缺少某功能”“必须导出到 Excel”“每次都要人工修复”等重复抱怨。  
**通过信号：** 多个产品被同一问题反复击穿，且用户已经在付费。  
**假信号：** 免费用户对边缘功能的愿望清单。

## 3. 工作流残留物

**来源：** Excel 模板、Notion 模板、Zapier Workflow、YouTube 操作教程、SOP、外包任务。  
**寻找：** 复制粘贴、跨系统搬运、定期核对、截图取证、人工分类与重复报告。  
**通过信号：** 用户已用模板、VA、脚本或多工具拼接解决。  
**假信号：** 低频但看起来复杂的流程。

## 4. 预算与交易证据

**来源：** Pricing Page、长期投放广告、Affiliate Commission、顾问报价、招聘薪资、Marketplace 付费评价。  
**寻找：** 谁在付钱、付多少、预算归属哪个部门、当前替代方案成本。  
**通过信号：** 多个小玩家持续收费，而不是只有一家明星公司。  
**假信号：** 下载量、点赞量、等待名单。

## 5. 技术、平台与监管变更

**来源：** API Changelog、Release Notes、政策文件、行业标准、平台弃用通知、安全与合规要求。  
**寻找：** 新能力第一次可用；旧接口失效；企业被迫迁移、留痕或证明合规。  
**通过信号：** 变化同时制造了明确 Deadline 和预算。  
**假信号：** 只有技术新颖，没有必须完成的任务。

## 6. 招聘、采购与服务市场

**来源：** Job Posts、RFP、Upwork、Agency Offer、行业协会、实施伙伴目录。  
**寻找：** 企业正在雇人反复完成什么；哪些服务被重复采购；哪些岗位只是“人肉 API”。  
**通过信号：** 同一交付在多家公司重复出现，并可抽成 SOP、Benchmark 或 Agent。  
**假信号：** 高度政治化、定制化、必须驻场的工作。

最终不是从六类数据中直接生成产品，而是建立一张证据表：

```text
任务是谁的
→ 现在怎么解决
→ 每年花多少钱
→ 最痛的失败是什么
→ 为什么旧供给解决不了
→ 我能否在两周内卖出最小结果
```

**本封行动：** 每个候选商机至少命中三类独立信号，其中必须包含一类预算证据；否则只进入观察池。
