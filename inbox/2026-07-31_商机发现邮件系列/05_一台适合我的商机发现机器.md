# 邮件 5｜一台适合我的商机发现机器

**Subject：** 不靠灵感，建立一台每月产出商机的机器  
**Preheader：** 系统负责持续扫描，真实支付负责最终裁决。

适合我的商机系统，不应该要求每天高能量输出。

它应该具备四个特征：

1. 主要处理数据、工具和工作流，而不是依赖人格表达。
2. 高能量时建设系统，低能量时系统仍能采集和筛选信号。
3. 每次验证都沉淀关键词、数据、名单、案例或自动化模块。
4. 任何分析最终都必须进入付费验证。

完整结构如下：

```text
六类高密度信号源
→ 自动采集与标准化
→ 痛点 / 预算 / 变化事件聚类
→ 四类结构变化归因
→ 六因子排序
→ 三红线否决
→ Top 3 最小 Offer
→ 五关验证
→ 真实支付
→ 人工交付
→ SOP / Dataset / Tool 产品化
→ pSEO + Email + Partner 分发
```

## 每月运行节奏

| 周期 | 系统动作 | 人的动作 | 输出 |
|---|---|---|---|
| 持续 | 抓取搜索、评论、Issue、Changelog、Job、Pricing | 无 | 原始信号池 |
| 每周一次 | 聚类、去重、变化检测 | 审核异常与误判 | 10 个候选问题 |
| 每两周 | 六因子预评分 | 解释缺口与预算来源 | Top 3 商机卡 |
| 每月 | 生成 Landing Page / Offer | 找 5 个买家或投少量精准流量 | 支付、拒绝或 Kill |
| 付款后 | 记录输入、判断、结果与售后 | 手工交付完整价值 | SOP 与 Dataset |
| 重复 N 次 | 识别稳定步骤与瓶颈 | 决定是否写代码 | Tool / Agent / Data Product |

## 预承诺规则

- 没有预算证据，不进入 Top 10。
- 没有明确第 100 个用户来源，不进入 Top 3。
- 没有真实支付，不写主程序。
- 两周无法完成最小 Offer，拆小或放弃。
- 每单不沉淀资产，不进入长期主线。
- 需要持续直播、社群维护或高情绪劳动，Founder Fit 直接降级。
- 单一平台掌握获客、支付或交付命脉，控制权系数归零。

## 最终商业形态

这套系统本身不急着作为产品出售。

第一阶段，它是内部 Engine，帮助筛选值得测试的 Payload。

当它连续发现并验证多个可付款机会后，才可能演化为：

- 垂直行业 Opportunity Radar
- Benchmark / Monitoring Subscription
- Lead Intelligence
- 行业变化 Newsletter
- 数据 API
- 带工作流的 Vertical Agent

真正的复利不是“每月多想几个点子”，而是：

```text
每次扫描让数据更完整
每次验证让判断规则更准确
每次成交让分发与案例更强
每次交付让产品化成本更低
```

**本封行动：** 先用半自动系统跑一个垂直领域，连续筛选 20 个候选并完成 3 个付费测试；在此之前，不开发“全网商机平台”。
