L1

同会话回填验证码

冻结租约，打码/识别后在原浏览器上下文回填，Persona 三元组不变。

账号池·冻结 代理·Sticky 保持 指纹·不变
L2

冷却 + 延迟重试

账号进 COOLDOWN，代理记 captcha_hit，任务延迟重入队，避免立刻重放。

账号池·冷却 代理·记分
L3

换出口保指纹

同 Geo 新 Sticky 住宅代理；指纹默认不换（换指纹更像盗号）；账号降权暖号。

账号池·降权 代理池·换亲和 指纹·保持
BAN

封号归因 + 卡池解封

三方归因后熔断代理或下线指纹模板；UNBAN 工单走卡池；恢复后进 RECOVERY 暖号池。

账号池·BANNED 卡池·UNBAN 代理·熔断? 指纹·下线?

四池协作时序（单次任务）

编排器串起四个资源池；卡池仅在注册/解封/2FA 时异步介入

  TQ->>O: 领取任务
  O->>AP: 按 grade/health 申请租约
  AP-->>O: Account + Cookie/Token
  O->>PP: 按账号亲和/敏感度匹配代理
  PP-->>O: Sticky Proxy
  O->>FP: 绑定长期 Fingerprint Profile
  FP-->>O: Profile ID
  O->>W: 下发 Persona 会话

  W->>T: 拟人化请求
  alt 业务成功
    T-->>W: 200 / 业务 OK
    W->>AP: 成功反馈 health↑
    W->>PP: 成功反馈
  else 验证码
    T-->>W: CAPTCHA
    W->>BUS: RiskEvent CAPTCHA
    BUS->>AP: 冻结租约 / COOLDOWN
    BUS->>PP: captcha_hit++
    Note over W: L1 同会话打码回填
  else 封号
    T-->>W: BAN
    W->>BUS: RiskEvent BAN
    BUS->>AP: BANNED health=0
    BUS->>SP: UNBAN 工单
    SP-->>AP: 解封成功 → RECOVERY
  end

RETRY BUDGET

重试预算

same_persona 1–2 · new_proxy 1 · new_account 2 · new_fingerprint 0–1（默认不换）

BINDING RULE

绑定铁律

会话内不拆散 Persona；刷新 Token 必须同代理同指纹；Geo/时区/语言对齐。

CIRCUIT

代理熔断

Closed → Open（冷却）→ Half-Open（探测）；多账号同挂优先判代理。
