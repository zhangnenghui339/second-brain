# 决策原则：红线与 MVP 反脆弱九门

> 用法：做任何重要决策前，读一遍这页。就这样，没有别的流程。  
> 分层：红线看上半页；「做不做 MVP」先过反脆弱九门。  
> 红线为跨项目通用否决条款；文末附录为 CareerRadar 映射示例。  
> 更新：想改就直接改，Git 历史就是版本记录。

---

## 三条红线（碰到直接否决，不用讨论）

### 红线 1｜不做「无私有资产 / 无工作流壁垒」的 AI 薄壳

- **禁：** 输入几句话 → 调大模型 → 吐通用内容的 Thin Wrapper。无自有数据、无独特流程、无独特供给，只赚 API 差价，极易被 ChatGPT / Claude / 平台原生 AI / AI Overview 免费替代。
- **允：** 「生成」只做秒级交付接口——输出必须绑在你掌控的投入资产上（私有/结构化数据、实测证据、专有工作流、独特供给），形态可以是报告、看板、批次结果。
- **一句话：** 禁替大模型卖壳；允用自有资产出结果。

### 红线 2｜不做「平台高风控执行层」与重运营主闭环

- **禁：**
  - 在第三方平台上替用户执行高风控动作（自动发帖、自动私信、自动投递、刷行为等）；
  - 可被平台原生功能一键抹平、且无自有资产承接的纯执行小工具当主产品；
  - 起量后必须靠持续人工客服/人工交付才能转的重运营主闭环。
- **允：** 只读观测、证据采集、用户侧自助；探索期可借用脆弱通道，但不得默认成长飞轮。
- **一句话：** 不当平台运动员，不当人力外包。

### 红线 3｜不砍「结果数据」与「可触达权」

必守两类底层管道（day-one 都不能断）：

| 资产 | 含义 | 为何砍不得 |
|---|---|---|
| **结果数据（Outcome）** | 用户用了之后实际发生了什么（是否达成承诺结果），不是只点了按钮 | 错过不可回填；定价、迭代、数据变现的凭证 |
| **可触达权（Email 等）** | 归你掌控、可反复低成本触达的名单/通道 | 没有触达权 = 一次性流量；有触达权 = 可再验证、再转化 |

- **禁：** 为求上线快或省追踪成本，削弱/推迟/省略结果数据采集，或做成「用完即走、不沉淀可触达权」的纯工具。
- **允：** 可以暂时弱变现；主闭环必须同时留结果数据口与可触达沉淀口。
- **一句话：** 现金可以后收；结果管道和名单管道 day-one 不能断。

## 九门上游：工作流候选方向生成器（不是第十门）

九门只负责回答「这个候选值不值得投入」；候选先从真实工作中产生：

```text
AI-native Global Solo Founder（长期身份）
→ AI Workflow Operator（默认 Work 状态）
→ 真实 Workflow
→ Distribution
→ 可重复 Friction
→ Script / 窄工具
→ Data / Outcome
→ 三红线、六因子、五关、九门
```

- **Founder–Workflow Fit：** 如果未来三年没人逼我，我还会不会每天做这件事？不会，就不作为长期主航道。
- **模式边界：** Operator 是默认状态；同一动作重复 ≥3 次且自动化 ROI 为正，才短暂进入 Builder。Codex 是工具，不是身份。
- **记录对象：** 记录 Workflow、Friction、Frequency、Cost、Workaround、Distribution、Outcome；不维护脱离真实工作的 Idea List。
- **项目边界：** CareerRadar 是垂直实验场，不是创业身份本身。

完整框架见 [`../../thinking/工作流候选方向生成器.md`](../../thinking/工作流候选方向生成器.md)。

## 框架分工：候选生成，六因子排序，红线否决，五关推进，九门放行

1. **候选生成层：** 优先从自身身份、真实工作流、分发现场与反复 Friction 中生成候选；跨市场迁移、数据异常、技术/监管/渠道变化只作补充，不证明商机成立。
2. **六因子排序层：** 用结构性供需缺口、变现强度、分发可复制性、交付可复制性、资产复利性、Founder Fit 横向比较候选；完整定义见 [`../../thinking/principles.md`](../../thinking/principles.md)。
3. **三红线：** 发现结构性风险立即否决，不进入后续验证。
4. **五关闸门：** 按分发 → 变现 → 需求 → 最小交付 → 产品化的时间顺序推进。
5. **反脆弱九门：** 对候选做完整体检，全部通过后才允许投入并构建 MVP。

> 六因子高分不等于可以动手；真实支付未验证时只能标记 `待验`。任何红线或九门否决项，都不能由其他维度的高分抵消。

## MVP 反脆弱九门（全部满足才动手）

> 面向 Solo 操盘手的反脆弱商业验证清单。用于飞轮选型、新功能、最小业务闭环；**全部满足**才允许购买域名、投入资金并开始构建 MVP。  
> 与 `prompts/_index.md` 的 Ponytail 分工：Ponytail 先杀伪问题；九门再筛「值不值得交市场学费」。  
> 与工作流候选方向生成器的分工：上游从真实 Workflow 产生候选；九门只过滤，不凭空产生 Idea。
> 撞红线直接否，不进九门。


**门1｜问题从自己来？（深度链接）**  
观察真实工作流里反复发生的 Friction；自己就是用户（或有等价高频反馈回路），不靠花几个月「理解想象中的用户」。
不做“大平台”，只做“微工作流”
答案客观、意图明确、可被一句搜索词表达、用完就走
**否决：** 纯脑暴痛点、问卷里的假需求、同温层抄来的「应该有人要」。

**门2｜视角是否够偏？（原创性来源）**  
原创不是想得比别人巧，是活得比别人偏：旅行、边缘场景、非同质经历 → 看到别人看不到的问题。  
**否决：** 只靠头脑风暴 / 趋势报告拼出来的同质点子。  
**软注：** 本门可与门1合并执行；单独列出是为防「自己有痛但痛点和所有人一样」。

**门3｜趋势窗口是否打开？（时间套利）**  
趋势须「刚被验证但未饱和」：不创造需求，做第一批产品化；是时间套利，不是需求发明。  
**否决：** 报告里很热、市场上已卷透；或只有概念热度、无人付费证据。

**门4｜是否紧贴新能力供给？（技术/流程跃迁）**  
技术供给创造产品机会：先玩新能力，发现某个结果第一次变得可用，再几天内挂支付。可包括通用 Search Demand 新意图、AI Agent 可自动化的整段流程等——关键是「供给刚到位」，不是「故事好听」。  
**否决：** 能力未就绪却硬做；或能力已人人可复制且无自有资产差（撞红线1）。

**门5｜让市场筛选，上线即收费？（付费意愿）**  
不做纯增长期；「用户喜欢」是噪音，付费转化才是信号；用付费墙代替调研。  
先验证付费意愿再写主程序（Fake-door / Day-1 收费）。  
放弃脑暴预测，用“极速量产”让市场做选择（5% 成功率法则）。  
“做多（Portfolio）”胜过“押注单点”

**否决：** 闭门半年再找用户；先免费做大规模再想变现；用买量撑起的注册/活跃当成「已经验证」；或零曝光就把「无人付费」当成需求不存在。


**门6｜自有受众与低获客是否可复制？（获客结构）**  
长期获客不能靠持续烧广告活下去。
“创业过程本身”就成了最大的免费广告，吸引了大量同行、媒体和早期采纳者.

**长线流量方式：** 主渠道必须是 **意图驱动的 pSEO 程序化长尾页** + 沉淀至 **自有 Email List**，实现零成本二次触达；自己掌控域名、用户数据、邮件列表。  

**否决：**  
- 生意永远靠买量续命；或流量/数据全在别人平台上，自己留不住；  
- **算逻辑阶段**已测出目标长尾词无有效搜索量，或后期必须依赖高价 PPC 才能获客。


**门7｜复杂度是否在两周一人上限内？**  
一个人约两周能独立搞定最小闭环；需要团队/融资才能起步的想法直接过滤，不管市场多大。  
“套壳”与“组合创新”并不可耻,极低的维护成本

**AI / Agent 专项：** MVP 的 AI 链路必须 **单向直铺（Linear Pipeline）**——输入 → 处理 → 输出，一条线走完。不写复杂的双向多 Agent 递归循环、不堆「越接越多」的工具链；Prompt 以能交付为准，不为完美调参拖过两周。  

**否决：** 宇宙飞船起步、技术栈过载、重销售才能成交；AI 项目因多 Agent / 递归编排在两周内收不了尾。

**门8｜零平台依赖？（系统控制权）**  
主链条若强依赖第三方（封号/断接口/法务风险/算法分发命脉），主闭环必须规避。探索性实测可软例外，不得默认成长飞轮。域名、用户数据、支付、名单须落在自有侧。  
**否决：** 命脉攥在单一不可控平台手里。


**门9｜停下后是否仍沉淀复利？（长期壁垒）**  
**Stop Test：** 停止主动拉客后，资产是否仍自动带来流量/数据/收入？每单须沉淀至少一种：pSEO / Email List / Benchmark·Outcome 数据 / 可复用模块（与红线3互锁）。粘住后优先同受众邻接扩张，不默认跳全新冷市场。  
**否决：** 用完即走、无资产；或只会短期套利、无复利沉淀。

### 全部过门后再动手（最终执行铁律）

→ 红线通过后，以上 9 门在逻辑推演与前端漏斗中全部满足，才允许购买域名、投入资金并开始构建最小业务闭环（MVP）。

→ 实验公式：`两周上线 × Day-1 收费 × 30 天真实付费`；不达标 → 下一枪（小失败不强制深度复盘）。

→ 门5 若因暂无支付数据被标记待验：其余门可先推演；**补齐真实支付漏斗数据并过门之前，铁律仍视为未通过**。

### 反模式（九门要切断的路径）

```
先决定「我要创业」
→ 在趋势报告里找赛道
→ 想象用户可能存在的问题
→ 闭门开发半年
→ 上线后再找用户
```

反馈延迟到终点，错误在此期间持续累积——主要由门1、门2、门5 联合否决。

## 五关闸门（新方向筛选，按分发→变现→需求→交付→产品化时序，每关是「能否继续」）

> 与三红线/九门的关系：九门是多维度全面体检，用于「要不要做 MVP」；这套五关是单一时间线上的「能否继续」检查点，用于新方向早期快筛。过五关不等于过九门，两者不互相取代。

| 关卡 | 问题 | 判据 | 时间 |
|---|---|---|---|
| G1 分发 | 第 100 个用户从哪来？成本？ | 具体渠道 + CAC 量级；「做 SEO」不算 | 天 |
| G2 变现 | 谁付？付多少？为何现在付？ | 该 CAC 下价格带已被验证 | 天 |
| G3 需求 | 愿为承诺付真实成本？ | 落地页 / 预售 / 邮件非零转化 | 1–2 周 |
| G4 最小交付 | 能手工交付一次完整价值？ | 有人付费并拿到结果 | 2–4 周 |
| G5 产品化 | 哪步值得写代码？ | 手工重复 N 次、瓶颈明确 | 之后才开始 |

(来源:2026-07-29 讨论)

## 做决策前问自己四个问题

1. **这件事是在当裁判，还是在当运动员？**
   我们的位置是中立验证方。任何让我们"自己也卖简历工具"的事都会毁掉这个位置。

2. **如果 AI 引擎明天自己做了这个功能，我剩下什么？**
   剩下数据和方法论 → 可以做；什么都不剩 → 别做。

3. **这个东西是 Engine 还是 Payload？**
   通用能力（爬虫、pSEO、prompt、测试框架）写进 Engine 仓库，CareerRadar 死了它们还能用。CareerRadar 专属的东西认了，就是消耗品。
   上位的 founder-fit 判别见 [`../../thinking/两种杠杆判别法_离机器近离文化远.md`](../../thinking/两种杠杆判别法_离机器近离文化远.md)：经验型杠杆依赖履历与文化，系统型杠杆依赖可验证结果；该判别法本身属于跨项目 Engine。

4. **在本周期预算内吗？**
   6 个月固定预算不突破，信号再好也不加注。

## 四个值得警觉的信号（看到了再回来翻这页）

- OpenAI / Perplexity 推出官方简历评测或工具排名 → 裁判位受威胁，考虑转型"给引擎供数据"
- Greenhouse / Lever 开放官方 parse API → "实测"不再稀缺，重心转向解读和 outcome 关联
- 大平台推出免简历的结构化 profile 直投 → 测试对象从 PDF 换成 profile，方法论不变
- AI 搜索引用越来越集中到大媒体 → 加码 email list，那是唯一没人能没收的渠道
