# 决策原则：红线与 MVP 反脆弱六门

> 用法：做任何重要决策前，读一遍这页。就这样，没有别的流程。  
> 分层：定位/红线看上半页；「做不做 MVP」先过反脆弱六门。  
> 更新：想改就直接改，Git 历史就是版本记录。

---

## 三条红线（碰到直接否决，不用讨论）

1. **不做"生成"类产品**——AI 让生成免费了，Builder/内容站打不过大厂免费额度。内容只是获客管道，不是资产。
2. **不做 auto-apply / 平台执行层的事**——那是 LinkedIn 的地盘，第三方必死。
3. **不砍 outcome 数据收集**——「这份简历有没有拿到面试」是唯一错过就补不回来的数据，任何决策与它冲突，它优先。

## MVP 反脆弱六门（全部满足才动手）

> 面向 Solo 操盘手的反脆弱商业验证清单。用于飞轮选型、新功能、最小业务闭环；**全部满足**才允许购买域名、投入资金并开始构建 MVP。  
> 与 `prompts/_index.md` 的 Ponytail 分工：Ponytail 先杀伪问题；六门再筛「值不值得交市场学费」。

### 1. 他人已验证？（验证宏观赛道）

→ 市面上已经有人赚钱了吗？如果没有，坚决不做（不交教育市场的学费）。进一步看清「验证」是否健康：

- **需求分布**：客户数量多且长尾分散，无绝对垄断。
- **生态活力**：已存在大量盈利的中小玩家。
- **切入缝隙**：Search Intent 可以被极度细分（Niche down）。
- **非标属性**：用户问题存在行业/场景差异，交付结果需要判断力，不完全是陷入价格战的标准品。
- **演进路径**：可以从轻服务切入，再逐步演进为纯产品，且不依赖大规模重度销售团队。

（注：以上越齐全，越适合 Solo 切入；缺大半则证明存在赢家通吃风险，仍算「未真正验证」。）

### 2. 先愿付费？（验证微观 Offer）

→ 赛道有人买，不代表用户愿意买「你」的账。能否通过极简落地页直接测出属于你的真实支付转化？

- **拒看虚荣指标**：不看点赞、不信问卷、不看 Waitlist。
- **唯一标准**：先测通真实的支付漏斗（点击购买或交不可退定金），确认你的文案和定价能完成商业闭环后，再写第一行主程序代码（Fake-door 验证）。
- **暂无数据可跳过**：若当前尚未跑过落地页/支付漏斗、拿不到真实付费数据，本门**先标记为「待验 / 跳过」**，不阻塞继续推演其余五门；但**不得**在本门未通过（或未补测）的情况下进入「全部过门后再动手」——补测前禁止买域名、投钱建主闭环。

### 3. 零平台依赖？（验证系统控制权）

→ 主业务链条强依赖第三方系统（如利用大厂漏洞、低价 ATS 试用账号等）吗？

- 若存在随时被封号、断开接口和法务警告的风险，主产品闭环必须立刻规避。
- **软门注记**：早期的探索性实测 / Kill Criteria 实验可以例外借用，但绝不能因此把极其脆弱的通道默认成长期主飞轮。

### 4. 资产秒交付？（验证履约边际成本）

→ 业务起量时，是榨干你的时间，还是边际成本归零？

- 能否用结构化数字资产（如行业模板、面经库、自动化脚本）实现秒级交付？
- 交付动作必须具备高度「可复制性」，坚决避开半人工、重交付的 SaaS 陷阱或高级客服模式。

### 5. 沉淀复利？（验证长期壁垒）

→ 这是检验你是「自由职业接单搬砖」还是「商业系统主理人」的分水岭。

- **The Stop Test（停工测试）**：如果下个月你停止主动拉客、停止人工干预，过去完成的订单和沉淀的资产，还能否持续、自动为你带来流量、数据或收入？
- **强制复利法则**：每做一单，除了换来一次性现金，必须强制沉淀出以下至少一种「复利资产」：
  - 带来自然长尾流量的 pSEO 内容页；
  - 归你完全掌控、可反复低成本触达的 Email List 订阅者；
  - 可以作为行业 Benchmark 的独有数据资产；
  - 能够不断复用在下一个产品里的自动化代码模块。

### 6. 自有受众与低获客成本？（验证获客可复制性）

→ 脱离了熟人网络和手动发帖，流量获取还能复制吗？获客成本够低吗？

- 严禁依赖高成本单次广告采买（Paid Ads）。
- 必须能够用细分的 SEO 策略拦截长尾流量，并在顺畅的交互中，将一次性的匿名访客沉淀为自己掌控的数字资产（Email List），实现零成本的二次触达与转化。

### 全部过门后再动手（最终执行铁律）

→ 只有以上 6 条在逻辑推演与前端漏斗中全部满足，才允许你购买域名、投入资金并开始构建最小业务闭环（MVP）。

- 第 2 门若因「暂无数据」被跳过：其余门可先推演；**补齐真实支付漏斗数据并过门之前，铁律仍视为未通过**。

## 做决策前问自己四个问题

1. **这件事是在当裁判，还是在当运动员？**
   我们的位置是中立验证方。任何让我们"自己也卖简历工具"的事都会毁掉这个位置。

2. **如果 AI 引擎明天自己做了这个功能，我剩下什么？**
   剩下数据和方法论 → 可以做；什么都不剩 → 别做。

3. **这个东西是 Engine 还是 Payload？**
   通用能力（爬虫、pSEO、prompt、测试框架）写进 Engine 仓库，CareerRadar 死了它们还能用。CareerRadar 专属的东西认了，就是消耗品。

4. **在本周期预算内吗？**
   6 个月固定预算不突破，信号再好也不加注。

## 四个值得警觉的信号（看到了再回来翻这页）

- OpenAI / Perplexity 推出官方简历评测或工具排名 → 裁判位受威胁，考虑转型"给引擎供数据"
- Greenhouse / Lever 开放官方 parse API → "实测"不再稀缺，重心转向解读和 outcome 关联
- 大平台推出免简历的结构化 profile 直投 → 测试对象从 PDF 换成 profile，方法论不变
- AI 搜索引用越来越集中到大媒体 → 加码 email list，那是唯一没人能没收的渠道
